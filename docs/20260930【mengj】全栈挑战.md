## 2. 挑战要求与实现对应

| 挑战要求 | 本项目实现 |

| 分步保存与进度恢复 | 五个主题阶段、34 项问题/确认项；增量保存、服务端 revision 和幂等回执；刷新后从首个未完成题恢复。 |

## 3. 核心流程

1. 访问首页，确认“仅填写虚构资料”的演示提示后创建匿名会话。
2. 在 `/assessment/profile`、`activity`、`lifestyle`、`nutrition`、`metrics` 五个阶段逐题填写；每次答案变更同步至后端。
3. 刷新页面或中断后重新进入，服务端返回已保存进度并继续完成。
4. 在确认页提交，服务端原子生成基础画像与免费方案轮廓。
5. 在结果页点击“演示解锁”，进入完整 28 天训练、恢复、饮食节律和变化情景报告。
6. 也可直接访问 `/demo` 对比固定合成数据的预览态与完整态。

## 4. 架构与数据设计

- 前端：Next.js 16 App Router、React 19、TypeScript、React Hook Form、React Query、Recharts。
- 后端：Next.js Route Handlers、Zod 契约校验、领域服务与 Presenter 分层。
- 数据库：PostgreSQL 16、Prisma 6。业务表包含 `users`、`sessions`、`assessments`、`assessment_results`、`subscriptions`、`payment_events`、`idempotency_records`、`rate_limit_buckets`。
- 一致性：同一用户仅一份草稿；写事务先锁用户行；结果、支付事件与幂等记录具唯一约束；支付事件通过复合外键保证测评、权益和用户归属一致。
- 部署：Vercel 承载应用，Neon 承载独立演示数据库；迁移与固定 Demo seed 由受控命令执行，避免部署构建并发迁移。

数据库关系与接口契约见仓库中的 [Prisma Schema](../prisma/schema.prisma) 与 [OpenAPI 文档](../openapi.yaml)。

## 6. 测试与复现

GitHub Actions 的最新发布配置验证已成功通过：[`verify #12`](https://github.com/Limerence-mj/health/actions/runs/36722926423)。

本地准备好 Node.js、Docker 和 PostgreSQL 后，可运行：

```shell
npm ci
docker compose up -d
npm run db:generate
npm run db:migrate
npm run db:seed
npm run verify
```

`npm run verify` 依次执行 lint、TypeScript、单元测试、真实 PostgreSQL 集成测试、生产构建和 Playwright 验收。测试覆盖的重点包括：

- BMI/能量/目标日期的正常、边界、缺失和非法输入；
- 授权前拒写、乱序保存、重复请求、乐观锁并发、刷新恢复与提交事务；
- 免费响应不泄漏付费字段、跨用户资源隔离、解锁幂等与丢响应后的恢复；
- 演示数据有效期、清理任务鉴权、Origin 与环境安全边界；
- 桌面/移动视口下的五阶段问卷、报告与演示解锁闭环。

接口可重放调用方式、请求字段与错误码见 README 和 `openapi.yaml`。本项目特意不提供真实支付调用示例；`/pay` 仅用于验证模拟权益状态机。

## 7. AI 协作复盘

AI 的实际使用、被否决的方案和原因已单独记录在 [AI复盘](./AI复盘.md)。核心原则是：AI 用于协助契约、迁移、边界样例与测试生成，但以数据库约束、真实 PostgreSQL 测试和浏览器验收作为最终判断依据，不把“能跑通”当作质量证据。

## 8. 演示边界与后续工作

- 这是可公开访问的演示站，不收集或长期保存真实健康信息；访客数据短期保留并支持主动删除。
- 健康计算是通用展示模型，不构成诊断或个体化医疗建议。
- 当前没有真实收款、第三方回调签名、退款、对账或财务审计能力；如进入商业环境，需独立接入并完成安全、法务、隐私和医学评审。
- 生产商业化前还应补齐平台/边缘限流、备份恢复演练、监控告警、数据库最小权限与真实支付风控。
