# 健康测评竞品对标整改方案 v3.1

## 1. 文档状态

- 状态：本地实施、评审整改与验收完成
- 日期：2026-09-28
- 任务等级：L3，高风险交付循环
- 来源依据：BetterMe Pilates `flow=2117` 浏览器实测、BetterMe 2026 官方问卷说明、v2 源码与自动化验收结果
- 核心边界：页面视觉、品牌、图片和文案保持原创；只对齐问卷信息架构、阶段节奏、分析反馈、个性化方案和解锁闭环。

## 2. 目标与验收口径

除页面视觉风格外，核心产品体验达到 90% 以上的功能还原度：

| 维度 | v3 验收条件 |
| --- | --- |
| 问卷覆盖 | 保留 5 个主题阶段和 34 项有效问题/确认项，覆盖目标、身体状态、活动、生活、饮食和身体数据 |
| 阶段节奏 | 每个主题阶段都有独立反馈或承接页，单选自动前进，多选和数字输入显式确认 |
| 分析反馈 | 展示可访问的分段分析进度，明确正在整理的维度，完成后才能进入答案确认 |
| 个性化结果 | 完整报告包含 28 天训练结构、7 天节奏样例、阶段路线、恢复和饮食行动，并能追溯到问卷答案 |
| 价值预览 | 免费结果展示个人起点和方案轮廓，但不泄露完整付费字段；完整方案继续通过服务端 Presenter 隔离 |
| 转化闭环 | 保留明确标注的模拟支付、确认、幂等恢复、权益激活和刷新后恢复，不伪装真实交易 |

不在本轮范围：复制竞品视觉、使用竞品素材、伪造用户评价或专家背书、接入真实支付、做医疗诊断。

## 4. 风险控制

- 健康建议保持一般性，不把 BMI、能量或日期写成诊断和保证。
- 健康数据授权位于首题，后端在授权前拒绝保存任何问卷答案。
- 个性化方案在提交时写入不可变结果快照，历史报告不重新读取可变测评字段。
- 免费与完整报告继续使用不同 Presenter 输出，客户端不能通过隐藏样式获得付费字段。
- 动画支持 `prefers-reduced-motion`，分析进度有文字状态和 `progressbar` 语义。
- 数据库使用前向迁移增加方案快照与共享限流桶；回滚需先停止新写入并保留已生成结果。

## 6. 验收结果

- `npm run verify` 通过：21 项单元测试、32 项真实 PostgreSQL 集成测试、Playwright 14 项通过且 2 项按既有配置仅由桌面端覆盖，Next.js 生产构建成功。
- 开发模式额外完成真实 Chromium 点击复验：主按钮创建会话返回 201 并跳转；页面不再展示题量统计、输入上下限或“回答组成画像”等内部实现文案。
- 免费报告仅返回 `planPreview`，不返回 `personalPlan`、能量字段或预测曲线；模拟解锁后返回 7 天节奏、三阶段路线、训练原则、恢复动作、饮食节律和个性化依据。
- 390×844 与 1440×1000 的完整报告实际 `scrollWidth` 分别等于 390 和 1440，均包含 7 个日程项，无横向溢出。
- 自托管 `Noto Sans SC Variable` 已消除测试容器中的中文缺字；390×844 与 1440×1000 最新截图均可读。
- 公网部署未执行；当前没有被授权的 Git 远端、云数据库或部署平台资源。
