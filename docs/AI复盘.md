# AI 辅助开发复盘

## 最终交付策略

本项目按 L3 高风险交付循环执行。风险并不来自代码规模，而来自健康数据、匿名访问凭证、付费字段权限、支付事件幂等和删除闭环同时存在。实施顺序采用“契约与纯函数 → 数据库约束 → 事务服务 → HTTP 边界 → UI → 真实数据库与浏览器验收”，避免先做页面后补一致性规则。

## 有效做法

- 先把输入、状态、错误码、revision 和幂等作用域冻结为 Zod/TypeScript 契约，前后端围绕同一语义实现。
- 算法保持纯函数，通过独立边界样例验证；物理范围外输入拒绝，目标方向、极端 BMI、大幅变化和能量窗口问题使用明确风险提示，不把钳制后的数值伪装成建议。
- 在应用事务之外再设置唯一约束、CHECK 和归属复合外键，使并发或代码缺陷不会轻易破坏核心不变量。
- 使用用户行锁统一所有写路径的锁顺序。支付先判断请求回执和旧事件，再判断当前权益，避免响应丢失后重复激活。
- 免费与完整报告使用不同 Presenter 白名单，而不是返回完整对象后由前端隐藏字段。
- 本地测试使用独立 PostgreSQL，而非内存数据库；Playwright 同时覆盖移动和桌面语义流程。

## 实际发现的问题

- Prisma CLI、`tsx`、Vitest 和 Next.js 对 `.env` 的加载行为不同。连接配置应由各入口明确加载，并通过真实命令验证，不能假设所有工具一致。
- 容器镜像拉取和大文件浏览器下载可能在调用端超时或被外部链路中断。恢复前应先读取真实状态，不能直接删除容器或重复初始化数据卷。
- 常见端口可能被其他项目占用；测试应使用隔离端口，不停止无关服务。
- 代理环境可能错误接管 localhost。E2E 明确设置 `NO_PROXY` 后，健康检查才与浏览器目标一致。
- 浏览器 trace 证明首轮四个失败是测试文案/URL 断言过窄，而非业务失败。保留截图与 trace 能避免为了“修测试”而错误修改产品。
- v2 不能只修改 Zod 与领域常量；数据库中独立 CHECK、完成态组合 CHECK、结果范围和预测形状都必须同步迁移，否则应用层契约会在事务末端被旧约束否决。已应用的迁移不回写，使用新的前向迁移修正。
- 恢复页面时不能只派生可见题号，还要在首次本地编辑前同步可变 `screenIndex`。否则 `dirty` 状态切换会让多选、数字或同意题跳回初始化题号；E2E 的刷新后继续场景能稳定发现此类问题。

## 仍需外部验证

- 当前已配置 Git 远端和 CI 工作流；没有用于公网部署的云数据库或平台授权，因此未执行公网部署。
- 真实商业化前需要替换模拟支付，接入订单、金额、币种、第三方事件签名、退款和财务审计。
- 需要在实际云账号验证数据库最小权限、连接池、平台速率限制、备份恢复、监控告警与回滚。
- 健康模型参数属于演示产品假设，若进入真实用户场景，需要医学、营养、法务和隐私评审。

## 可复用结论

对于同时包含匿名会话、敏感输入和权益解锁的原型，“能演示”不等于“闭环”。最小可信交付应至少证明：物理非法输入被拒绝、风险组合有清晰提示、免费响应不泄漏、重复事件不重复生效、并发写入不丢更新、删除能清干净、公开 demo 不切换个人身份，并且这些结论来自数据库和浏览器证据，而不是只看源码推断。
